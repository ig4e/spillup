# Fleet operations research

Spillup's main jobs are onboarding a machine, keeping its skills and tools in step, moving accounts safely, and setting up T3 Code links. The v0.4 changes address three gaps across these jobs.

| Tool or pattern | What Spillup uses or could add |
| --- | --- |
| Ansible check mode previews playbook work before applying it. [Check mode](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_checkmode.html) | `spinup setup --plan` previews the role and ordered steps. The CLI and dashboard list local configuration changes and identify checks that need a live installer. |
| Rundeck shows running steps, captures execution history, and supports time limits. [Jobs](https://docs.rundeck.com/docs/manual/jobs/index.html) [Job timeouts](https://docs.rundeck.com/docs/manual/jobs/creating-jobs.html#timeout) | Setup and system updates now report stages and recent output. Activity retains 100 dashboard actions and 50 setup or update jobs across restarts. A repeated fleet rollout checks each running version and its health before advancing. |
| Syncthing reports connection and disconnection as distinct events. [Connected](https://docs.syncthing.net/events/deviceconnected.html) [Disconnected](https://docs.syncthing.net/events/devicedisconnected.html) | Machines records health transitions for Tailscale, Spillup, account sync and T3 linking. |
| Tailscale separates network reachability, application grants, and configuration audit events. [Grants](https://tailscale.com/docs/features/access-control/grants) [Audit logging](https://tailscale.com/docs/features/logging/audit-logging) | Dashboard administration and library sync now require device ownership or a management credential where applicable. Separate capabilities for fleet management, library sync, and inference would let teams delegate access more precisely. |
| CLIProxyAPI Management Center handles OAuth, provider configuration, and quota views. [Management Center releases](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/releases) | Workers can view anonymous provider health and usage windows in Accounts. Account changes use the existing management UI. |

Use `spinup rollout` to preview the latest stable release. `spinup rollout --apply` runs on the configured hub and updates workers before standbys. It checks a separate serving holder before each replacement and verifies each running version before the next machine. The serving holder is deferred. Move the accounts to a synced standby, or schedule a manual update when the hub is the sole holder. Machines on releases without the staged-update endpoint need one local update first. The existing automatic update setting is independent and can be turned off when managing a fleet on a schedule. Unattended updates defer a serving holder without a synced standby.
