# Fleet operations research

Spillup's main jobs are onboarding a machine, keeping its skills and tools in step, moving accounts safely, and setting up T3 Code links. The v0.4 changes address three gaps across these jobs.

| Tool or pattern | What Spillup uses or could add |
| --- | --- |
| Ansible check mode previews playbook work before applying it. [Check mode](https://docs.ansible.com/projects/ansible/latest/playbook_guide/playbooks_checkmode.html) | `spinup setup --plan` previews the role and ordered steps. The CLI and dashboard list local configuration changes and identify checks that need a live installer. |
| Rundeck shows running steps, captures execution history, and supports time limits. [Jobs](https://docs.rundeck.com/docs/manual/jobs/index.html) [Job timeouts](https://docs.rundeck.com/docs/manual/jobs/creating-jobs.html#timeout) | Setup and system updates now report stages and recent output. Activity retains 100 dashboard actions and 50 setup or update jobs across restarts. A repeated fleet rollout checks each running version and its health before advancing. |
| Syncthing reports connection and disconnection as distinct events. [Connected](https://docs.syncthing.net/events/deviceconnected.html) [Disconnected](https://docs.syncthing.net/events/devicedisconnected.html) | Machines records health transitions for Tailscale, Spillup, account sync and T3 linking. |
| Tailscale separates network reachability, application grants, and configuration audit events. [Grants](https://tailscale.com/docs/features/access-control/grants) [Audit logging](https://tailscale.com/docs/features/logging/audit-logging) | Dashboard administration and library sync now require device ownership or a management credential where applicable. Separate capabilities for fleet management, library sync, and inference would let teams delegate access more precisely. |
| CLIProxyAPI Management Center handles OAuth, provider configuration, and quota views. [Management Center releases](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/releases) | Workers can view anonymous provider health and usage windows in Accounts. Account changes use the existing management UI. |

Use `spinup rollout` to preview the latest stable release. `spinup rollout --apply` runs on the configured hub and updates workers before standbys. It checks a separate serving holder before each replacement and verifies each running version before the next machine. The serving holder is deferred. Move the accounts to a synced standby, or schedule a manual update when the hub is the sole holder. Machines on releases without the staged-update endpoint need one local update first. The existing automatic update setting is independent and can be turned off when managing a fleet on a schedule. Unattended updates defer a serving holder without a synced standby.

## Ranked feature proposals

The first three address problems a fleet owner can encounter during normal work. The remaining four build on the existing updater, T3 desktop pairing and Activity history. Effort is a relative engineering estimate.

| Priority | Feature and first delivery | Why it matters | Effort | Reference |
| --- | --- | --- | --- | --- |
| 1 | **Export a support snapshot from Doctor.** Preview a local download with pseudonymous machine names, versions, failed checks, response codes and recent job outcomes. Build the export from a field allowlist. | A user can report a quota or pairing failure without pasting credentials, account identifiers or raw logs. | Small–medium | [NetBird debug bundles](https://docs.netbird.io/help/troubleshooting-client) · [Cockpit diagnostic reports](https://docs.cockpit-project.org/cockpit-guide/368/guide/feature-sosreport.html) |
| 2 | **Show live stream quality.** Add an optional Remote panel for received and displayed frames, dropped frames, latency, bitrate and transport. Link to the existing Doctor path check. | When video stutters, the user can distinguish a slow relay from frames the browser struggles to display. | Medium | [Moonlight performance statistics](https://github.com/moonlight-stream/moonlight-docs/wiki/Frequently-Asked-Questions) · [Tailscale connection types](https://tailscale.com/docs/reference/connection-types) |
| 3 | **Restore an earlier shared instruction or skill.** Keep a bounded history of changed library files. Preview the diff and restore the chosen content as a new library revision. | Users can undo an edit that has already synced to other machines. Spillup already restores removed skills and rolls back package releases. | Medium | [Syncthing file versioning](https://docs.syncthing.net/users/versioning.html) |
| 4 | **Schedule a maintenance window per machine.** Show the next window in local time and defer restarts while a terminal, desktop stream or provider request is active. Keep the existing holder and standby checks. | A release can reach an intermittently connected laptop without interrupting an active session. | Medium | [Coder scheduling and activity detection](https://coder.com/docs/user-guides/workspace-scheduling) |
| 5 | **Retry the failed machines in a rollout.** Persist the target release digest and each machine’s outcome. A retry rechecks identity, version and holder state before updating outstanding machines. | After a machine sleeps or disconnects, the operator can resume from a recorded result and see which machines were deliberately deferred. | Medium | [Rundeck retrying failed nodes](https://docs.rundeck.com/docs/manual/jobs/job-retry-failed-nodes.html) |
| 6 | **Link failed actions to their diagnostics.** Add host, component and outcome filters to Activity. A correlation ID connects each failed action to its job and relevant Doctor check. | The user can follow one failed operation without searching several screens or collecting raw system logs. | Small–medium | [Cockpit log filters and entry views](https://docs.cockpit-project.org/cockpit-guide/368/guide/api-logs-html.html) |
| 7 | **Remember recent T3 destinations.** On the user's device, save a chosen machine and project folder. Offer to reopen its backend and copy the folder path, or launch the project directly if T3 exposes that action. | Returning to work on a second computer takes fewer steps. Store only the destination metadata. | Small–medium | [JetBrains Gateway remote sessions and recent projects](https://www.jetbrains.com/help/idea/work-inside-remote-project.html) |
